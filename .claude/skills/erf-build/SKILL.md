# Сборка .erf

Тот же MCP-tool `build_external_processing(kind="report", …)` → `tools/erf_build.py`. Контейнер v8, copyinfo и способ проверки — как в **epf-build** (прочитай его первым). Здесь — только то, что специфично для отчёта.

## Перед работой
1. Прочитай `epf-build` и этот файл, включая «Журнал находок».
2. Рецепты параметров tool для runtime-агента — раздел «Внешний отчёт» в `knowledge/заметки/сборка_обработок.md`.

## Где что лежит
| Что | Где |
|---|---|
| Настройки варианта (структура, таблица, диаграмма, оформление, польз. поля, параметры вывода, варианты) | `tools/erf_settings.py` (`variant_xml`); формат — по выгрузке CF (`scripts/_dcs_skeleton.py <Template.xml> <тег>` печатает скелет узла) |
| Выгрузка макета СКД платформой (проверка: что платформа приняла) | `scripts/_erf_dump.py <файл.erf> [подстроки]` |
| Своя форма отчёта (поля, ТЧ, палитра, события) | `tools/erf_form.py` (`report_form`: правит эталон `form_report.txt`, элементы берёт из epf_build) |
| Сборка отчёта, схема СКД, настройки | `tools/erf_build.py` (`build_dcs`, `_settings_xml`, `query_fields`, `query_parameters`) |
| Разбор СКД чужих отчётов | `tools/epf_dcs.py` |
| Стандартная форма отчёта (Сформировать / Настройки) | `tools/data/erf_tpl/form_report.txt` (эталон владельца; подставляются заголовок и TypeId) |
| Смоук | `python scripts/_smoke_erf_build.py [--platform] [--cf=…]` |
| Роутинг | `_det_build_epf` ловит «внешний отчёт / erf / эрф»; «отчёт по продажам» без этого — `build_report` |

## Формат (кратко)
- Классы метаданных: отчёт `e41aff26`, форма `a3b368c0`, макет `3daea016`.
- Макет СКД = заголовок `<6×u32: 0, N вариантов, len схемы, 0, len настроек, 0>` + XML схемы + XML настроек (по одному на вариант) + пустая схема-хвост.
- Поля — из колонок **последнего** `ВЫБРАТЬ` без `ПОМЕСТИТЬ`; каждой колонке нужен `КАК`; `*` нельзя.
- Каждый `&Параметр` запроса обязан быть описан в `parameters`.
- `datasets` + `links` — несколько наборов; без связей одноимённые колонки сливаются. `calculated_fields` — выражения СКД, имя не совпадает с колонкой. `filters` — отборы по умолчанию (поле, вид сравнения, значение, use=false — выключен).

## Цикл работы: собираю я, проверяет владелец
Цикл тот же, что в `epf-build` → «Цикл работы»: 1С:Предприятие сам не запускаю, владелец открывает файл и присылает скриншоты или ошибки. Что добавляется для отчёта:
- **Без клиента**: смоук `_smoke_erf_build.py`; разбор своего erf через `inspect_external_processing` (схема СКД, параметры, поля); по возможности выгрузка Конфигуратором и обратная загрузка (`--platform`).
- **Чек-лист владельцу**: Файл → Открыть → «Настройки…»: какие параметры заполнить → «Сформировать» → какие группировки и колонки должны быть, где итоги.
- **Типовые ответы**: «Поле не найдено» или «Параметр не установлен» — сверить колонки последнего `ВЫБРАТЬ` и список `parameters`; пустой отчёт — сначала спросить период и проверить данные через `build_report`/`execute_query`, только потом искать ошибку в схеме.
- Находки, которые владелец подтвердил, — с пометкой **[владелец]**.

## Параметры tool и устройство
- `build_external_processing(kind="report", query, parameters, resources, group_by, order, datasets, links, calculated_fields)`.
- Форма — шаблон `form_report.txt` (панель «Сформировать/Настройки»): подставляются заголовок и TypeId; в Form.bin никаких реквизитов отчёта нет.
- Режим совместимости (8.2.16) касается и выражений СКД/вычисляемых полей: функции новее не использовать; в модуль отчёта (если есть) — те же правила, что в `epf-build` → «Устоявшиеся приёмы».
- Пустой отчёт ≠ ошибка схемы: сначала период и данные (`build_report`/`execute_query`), потом схема.

## Не умеет (на 2026-10-26)
Библиотечные картинки платформы в макетах (только свои PNG/JPEG/GIF/BMP), непроверенные подпараметры диаграммы кроме ТипДиаграммы.ВидПодписей/ЦветФона/Шрифт/МинимальноеЗначение/МаксимальноеЗначение, QuickAccess для отборов, произвольный элемент справочника в отборе по имени (только предопределённые, пустая ссылка, значения перечислений). Остальное в tool собирается и проверяется.

## Обновление скилла (обязательно после каждой сборки/правки)
Правила те же, что в `epf-build` → «Обновление скилла»: новая находка → строка в журнал `- ГГГГ-ММ-ДД [владелец|выгрузка|гипотеза] суть → где в коде`; ошибка, которую прислал владелец, вместе с причиной — в таблицу «Ошибка → причина» скилла epf-build (в начале строки пометка «erf:»); опровергнутое — исправить в тексте; важное для runtime — в `knowledge/заметки/сборка_обработок.md`. Находка про контейнер/формы, общая с epf, — пиши в `epf-build`, а здесь не дублируй. Ничего нового — файл не трогать.
