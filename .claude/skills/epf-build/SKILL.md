# Сборка .epf

Платформа владельца 8.3.24, **обычное приложение, обычные формы**. Конфигурация любая — имена объектов только из tools/Qdrant.

## Перед работой
1. Прочитай этот файл целиком, включая «Журнал находок» внизу — там грабли прошлых сборок.
2. Рецепты для runtime-агента (что умеет tool, шаблоны BSL, диаграмма Ганта): `knowledge/заметки/сборка_обработок.md`. Не дублируй их здесь — сюда пишется то, что нужно **разработчику сборщика**.

## Формат (кратко)
- Контейнер: оглавление, блоки 512, deflate верхнего уровня, вложенные `<id>.0` (`info/text`, `form/module`). Оглавление >512 байт занимает несколько страниц — читать размер **страницы**, не документа.
- Привязка поля к реквизиту = запись форм-реквизита `{idЭл,{2,{1},{0,<GUID реквизита>}}}` + запись в `copyinfo` (по возрастанию id) + путь `{{0,<GUID>},<TypeId>,{-1}}`. Без copyinfo поле видно, но значение не доходит до модуля.
- События формы: блок после `59d6c227…`, `{N,{<код>,e1692cc2-…,{3,"<Процедура>",…}}}`; 70000 ПередОткрытием, 70001 ПриОткрытии, 70002 ПередЗакрытием, 70003 ПриЗакрытии … 70011. Без записи событие **не вызывается**, даже если процедура есть.
- События поля ввода: список перед `{8,L,T,R,B…` в узле `381ed624…`; 2147483647 ПриИзменении, 1 НачалоВыбораИзСписка, 2 НачалоВыбора, 3 Очистка, 4 Регулирование, 5 Открытие, 7 ОбработкаВыбора, 10 ОкончаниеВводаТекста, 11 АвтоПодборТекста.
- ТабличноеПоле: `{N,` перед колонками = их число; редактируемость — бит 1024 маски `{19,<маска>` + флаг `2,0,1`; без блоба `tbl_editor.txt` — «Ошибка формата потока».
- Ссылочные типы: GUID из `<Класс>/<Имя>.xml` выгрузки (runtime — зеркало Qdrant `ensure_mirror`).
- Узел элемента: `{GUID типа, id, {свойства…}, [данные диаграммы], {8, раскладка}, {14,"Имя",…}, {0}}`. Список событий — внутри свойств, путь от узла: (2,2) у большинства, (2,4) ПолеВвода/ТабличноеПоле, (2,5) Переключатель, (2,17) ПолеТабличногоДокумента; у диаграмм (версия узла 74) — не в этом списке: прямо в узле перед `{3,3,{-22}}` стоит флаг 0/1, при 1 следом `{N,{код,e1692cc2…}}` (шаблон `@@EVENTS@@`, `_ctl_events_text`).
- Раскладка `{8,L,T,R,B,1, 6 пар привязок, 4 списка ссылок {0,id,сторона}, 0,0,0,O1,O2,0,0}`. Без связей с соседями: привязка размера к себе — `{2,<id>,0,<высота>}` (2-я пара) и `{2,<id>,2,<ширина>}` (4-я пара), как у брошенного на форму элемента (`_ctl_layout`). O1/O2 — порядковые номера, платформа терпит любые растущие.
- **Привязки сторон** (сверено по 4670 формам выгрузки: 4820 из 4820 обратных ссылок, 0 пропусков). Четыре первые пары раскладки — стороны элемента верх/низ/лево/право, пятая и шестая всегда свободны. Пара `{0,{2,объект,сторона,отступ},{2,-1,6,0}}`: объект `0` форма, `-1` нет, иначе id элемента; сторона цели 0 верх / 1 низ / 2 лево / 3 право (5 встречается редко, не разобрана), `6` — нет; граница элемента = граница цели + отступ (у низа/права формы отступ отрицательный). Вертикальные стороны привязываются к вертикальным, горизонтальные к горизонтальным. Вторая запись пары (двойная привязка) бывает у ~1% элементов, не пишем. Сосед обычно: верх к низу соседа (`{2,N,1,отступ}`, 600 случаев на 300 форм), лево к правому краю соседа (`{2,N,3,…}`).
  **Обратные ссылки обязательны**: привязка `{2,X,s}` на стороне k элемента E = запись `{0,E,k}` в списке s элемента X (четыре списка «счётчик + ссылки» после шести пар раскладки). Для X = форма — те же списки лежат в **реестре формы** (шаблон `form_default.txt`: `26,0,1,{0,3,1},2,{0,2,2},{0,3,2},2,{0,2,3},{0,3,3},0,0` = по 6 сторонам счётчик и ссылки). Раньше сборщик заполнял реестр только для правого края полей/таблиц, поэтому `anchor`/`fill` у элементов палитры реестра не имели [гипотеза: из-за этого они не растягивались макетом, см. журнал 2026-10-26]. Теперь `epf_build._bind_controls` строит пары, обратные ссылки и реестр сразу (`bind`/`anchor`/`fill`); у `_REG_BASE` (epf) и `erf_form._REG_BASE` — реестр шаблонов.
  Остаётся неописанное: «лишние» зеркальные ссылки (самопривязка верха к своему низу при низе к форме добавляет `{0,E,1}` в список стороны 0 — 86 случаев на 300 форм), не пишем; смещение до `26` перед реестром не расшифровано (в шаблонах 26).
- **Порядок обхода (Tab)** хранится в раскладке каждого элемента `{8,…,O1,O2,0,0}`: O1 — уникальный порядковый индекс элемента (0,1,2… как в списке элементов), O2 — порядок обхода (его показывает панель свойств, меняется в конструкторе; у надписи и её поля O2 общий). По 854 формам выгрузки O1 повторяется только в 23% форм, O2 — свободный. Параметр `controls[].tab_order` задаёт O2 (в варианте `anchor`/`fill` не действует: там чисел нет). Группа `{0,3,2},N,…` в форме — НЕ порядок обхода, а реестр привязок к самой форме (см. «Привязки сторон» ниже): для элементов без привязок к форме туда ничего добавлять не нужно. Раньше у `controls` O1=O2=cid-2 и O1 совпадал с O1 надписи таблицы (6,6) — теперь O1=cid-1.
- Коды событий элементов (по 4670 формам выгрузки): ПриИзменении 2147483647 у полей/флажка/переключателя/полосы/календаря; Нажатие 0 у кнопки/надписи/картинки; ТабличноеПоле 34 Выбор, 35 ПриАктивизацииСтроки, 42 ПередУдалением, 47 ПриВыводеСтроки …; ПТД 1 ОбработкаРасшифровки, 2 ПриАктивизацииОбласти, 7 ПриИзмененииСодержимогоОбласти; полная таблица — `_CTL_EVENT_CODES`.
- **Макет (MOXCEL)** = `<id>` (метаданные узла: `{1,{2,0,{3,{1,0,id},"Имя",{1,"ru","Синоним"},"Комментарий",0,0,GUID0,0}},0}`) + `<id>.0` (deflate от `MOXCEL + нулевой байт` + `<HHH 8,1,12>` + BOM + скобочный текст); в корне — коллекция `{3daea016-…,N,id…}`; в copyinfo макеты НЕ входят. Устройство текста — докстринг `tools/mxl_build.py`. Формат расшифровывается так: маленький XML макета → `mxl_lab.py` → платформа записывает MOXCEL → читаем скобки; одно свойство за опыт.
- Формат MOXCEL: `{маска, значения по возрастанию битов}`: 0x1 шрифт, 0x2/0x4/0x8/0x10 рамки лево/верх/право/низ (индекс таблицы линий), 0x20 цвет рамки, 0x40 высота, 0x80 ширина, 0x100 гориз. (Left 0, Center 6, Right 2), 0x200 вертик. (Top 0, Center 24, Bottom 8), 0x400 цвет текста, 0x800 цвет фона (цвета — индекс палитры, первые два — системные; `{3,0,{BGR}}`), 0x4000 размещение (Auto 0, Cut 1, Wrap 3), 0x8000 заполнение (Text 0, Parameter 1, Template 2). Индексы форматов в ячейках — с 1, 0 = без формата. Линия `{4,0,{0},стиль,толщина,0,f527dc88-1d39-40b3-bcbb-d98b690ead68,разрыв}`: None 0, Solid 1, Dotted 2, Double 3, ThinDashed 4, ThickDashed 5, LargeDashed 6. Объединение `{кол,стр,кол+w,стр+h,0}`, область `{тип,кол1,стр1,кол2,стр2,GUID0}` (Rows 1, Columns 2, Rectangle 3; границы включительно), имена областей — по алфавиту. Ячейка: параметр — язык `""`, текст — `"ru"`; расшифровка — маска 24 и строка перед текстом.
- **Как расшифровывать свойство (порядок)**: 1) `_props_audit.py <epf> --full` — копии с «НЕТ В КАРТЕ / РАСХОЖДЕНИЕ»; 2) если различий много, а чистого эталона нет — `_props_mode.py <epf> <Форма> [--node N] [--skip 1,2,3,4]`: свойство видно как путь, на котором отклоняется только его копия (у диаграмм `--node 3`; у ПолеТабличногоДокумента пропускать координаты 1–4); 3) побочные различия не принимать за позицию: `[2,N,0,16]` 0→2 и `[2,1,43]` 2→1 (появляются при смене цвета/рамки), координаты и порядок обхода в раскладке `{8…}`, длина раскладки; 4) цвет, совпавший с умолчанием внутри блока (чёрный=0), меняет только `{3,<тип>,…}` — путь блока, а не вложенного значения; 5) копию «без различий» не выдумывать: КонтекстноеМеню/АвтоКонтекстноеМеню и СоставДаты в узле элемента не хранятся. Свойства с парной записью (полосы прокрутки `[2,16]`+`[2,32]`, ТипДиаграммы `[3,20]`+`[3,139]`, палитра `[3,118]`+`[3,196,1]`) записаны основной позицией и `echo`.
- **Свойства элементов (карта `ordinary_form_props.json`, ~225 свойств)** расшифровываются эталонами: форма на тип, `<Тип>_Эталон` + копии `<Тип>_<Свойство>` (одно изменённое свойство), `scripts/form_bin_map.py <epf> --validate D:/conf_test`. Копия без различий = свойство зависит от родителя (АвтоПереносСтрок без многострочного) или лежит на уровне формы; смотреть различия глазами, не только лог. `АктивизироватьПоУмолчанию` — свойство формы (блок `top[1][2][1][1]`, слот перед `"5","64"`), смещение «−10 от конца» нестабильно. Блок `{14,"Имя",<ИсточникДействий>,<ИзменяетДанные>,<ПропускатьПриВводе>,<ПервыйВГруппе>}` общий для всех типов. Позицию не угадывать — второй эталон.
- Ширина формы ≠ 400: кроме габаритов формы менять панель страниц `{2,<W-8>,1,1,3,0,0,8,0}` и верхнюю командную панель `{8,0,0,<W>,25,1,`.

## Цикл работы: собираю я, проверяет владелец
**1С:Предприятие (ENTERPRISE) сам не запускаю.** Файл открывает и проверяет владелец, а потом присылает скриншоты или текст ошибки. Мои проверки только статические.

1. **Собрать**: `build_external_processing` или `write_epf` → `exports/<Имя>.epf`.
2. **Проверить без клиента**:
   - смоук `python scripts/_smoke_epf_build.py`;
   - обратный разбор своим же `inspect_external_processing`: формы, реквизиты, события, модуль на месте;
   - `bsl_warnings` пустые (модальные окна и т.п.);
   - по возможности `verify_with_platform` (выгрузка Конфигуратором `/DumpExternalDataProcessorOrReportToFiles`): проверяет метаданные, Предприятие не открывает;
   - синтаксис BSL: `python scripts/_bsl_syntax_check.py <файлы одного модуля>` (OneScript `-check`): ловит незакрытые блоки, скобки, опечатки в ключевых словах; модуль объекта и каждую форму — отдельным запуском;
   - имена методов/свойств платформы сверять со справкой `knowledge/справка_платформы/синтаксис_помощник/<Тип>.<Член>.md` (синтаксис-чекер их не проверяет);
   - логика вывода: `python exports/gantt_src/sim_check.py` — выполняет настоящий `show.bsl` в OneScript с заглушкой поля табличного документа, рисует раскладку текстом и ловит пересечения объединённых ячеек. Для нового вывода в табличный документ делать такую же имитацию (заглушка класса с экспортными свойствами только из справки — опечатка в свойстве даст ошибку).
3. **Отдать владельцу** путь или `download_url` и короткий чек-лист «что проверить»: открыть Файл → Открыть, какие поля заполнить, какую кнопку нажать, что должно получиться. Отдельно перечислить, что в этой сборке новое и ещё не проверялось в клиенте.
4. **Разобрать ответ владельца**:
   - текст ошибки 1С → найти причину в Form.bin, шаблоне или BSL; сначала проверить таблицу «Ошибка → причина» ниже;
   - скриншот → сравнить с ожидаемым (расположение, подписи, данные); непонятно, что не так, — спросить, а не гадать;
   - исправить → пересобрать → снова п.2–3. Каждая итерация — новый файл с тем же именем, без вариантов «на выбор».
5. **Записать** в журнал, что подтвердил владелец (**[владелец]**), что видно только по выгрузке (**[выгрузка]**), что пока гипотеза.

Оракул платформы (Конфигуратор, без Предприятия): пустую ИБ создаёт `1cv8.exe CREATEINFOBASE File=…` через `subprocess` (из Git Bash exe сразу возвращает 1; `powershell -ExecutionPolicy Bypass` классификатор запрещает). Полную CF в тестовую ИБ не грузить: `/LoadConfigFromFiles D:\conf_test` идёт ~10 мин, а `/UpdateDBCfg` падает 0xC0000005 — для проверки ссылочных типов собирать мини-конфигурацию (выгрузить пустую ИБ, добавить `<Класс>/<Имя>.xml` с InternalInfo из conf_test + пустые Properties/ChildObjects).

Если для проверки не хватает эталона (новое свойство или элемент формы), попросить владельца сделать в Конфигураторе эталонную epf с этим элементом, а не угадывать позицию.

## Ошибка → причина (пополнять)
| Что прислал владелец | Причина / где смотреть |
|---|---|
| «Ошибка формата потока» при открытии формы с таблицей | нет блоба `tbl_editor.txt` у колонки или неверное число колонок `{N,` |
| Поле на форме есть, но значение не доходит до модуля | нет записи реквизита в `copyinfo` или путь `{{0,<GUID>},<TypeId>,{-1}}` |
| Процедура `ПриОткрытии` и т.п. не срабатывает | событие не записано в блок после `59d6c227…` |
| Повторное открытие формы падает на `ЭлементыФормы.Добавить` | элемент создаётся каждый раз, а должен один раз (`Если … = Неопределено`) |
| Разовое «Предупреждение безопасности» при открытии | штатное поведение платформы, не ошибка (и на каждый новый хэш файла) |
| «Поле объекта не обнаружено» на `ЭлементыФормы.ОсновныеДействияФормы` | у `extra_forms` нет панели основных действий — обернуть в `Попытка` |
| «Процедура или функция не определена» (`СтрРазделить`, `Абс` …) | режим совместимости 8.2.16: функция новее или её нет в 1С вообще — `_bsl_syntax_check.py --compat 8.2.16` |
| «Преобразование значения к типу Число» (`Макс(число - Неопределено)`) | переменная модуля формы не инициализирована до первой проверки |
| «Ошибка при вызове метода контекста» у `ПодключитьОбработчикОжидания` | интервал < 1 с без `Однократно=Истина` |
| Ожидается имя процедуры / «Встроенная функция может быть использована только в выражении» | имя процедуры совпало со встроенной функцией (`Найти`, `Сообщить`, `Формат`…) — называть по-другому, например `НайтиПустыеДокументы` |
| Отчёт `/Execute` не открывается | erf: так платформа отчёты не открывает даже эталон — только Файл → Открыть |

## Устоявшиеся приёмы BSL и вывода (проверено владельцем в клиенте)
Свёрнуто из журнала по графику Ганта; сюда — только то, что подтверждено.
- **Режим 8.2.16** (Configuration.xml): новее 8.2.16 нельзя (`СтрРазделить`, `ПолучитьИнформациюЭкрановКлиента`). `Абс` в 1С нет → `Макс(a-b, b-a)`. `Формат(0,"ЧГ=0")` даёт пустую строку → `Строка(Цел(x))`.
- **Размер формы**: события изменения размера у обычной формы нет. В `ПриОткрытии` размеры ещё не итоговые (форма и поле = 400) → только создать элемент и `ПодключитьОбработчикОжидания("ПервоеПостроение", 0.1, Истина)` (интервал <1 с — только с `Однократно`). Дальше опрос раз в 1 с (минимум платформы): резкая смена размера — строить на первой проверке, непрерывное растягивание — ждать, пока замрёт. Перед подключением — `Отключить` в `Попытке` (повторное открытие). Переменные модуля формы — инициализировать до первой проверки.
- **Окно на весь экран** из кода не развернуть; размер — в самой форме (`extra_forms[].width/height`), профиль пользователя приоритетнее. Элемент с `fill:True` и `panels=False` растягивается без кода.
- **Колонки ПТД**: ширина хранится с шагом 1/8 символа и округляется вниз; 1 символ ≈ 7 px. Дробную ширину не задавать — раздавать целые «восьмые» (Брезенхэм) сериями `Область(,c1,,c2).ШиринаКолонки`, проверять readback. Горизонтальной прокрутки избегать (при прокрутке справа остаётся пустое место — свойство платформы): если не помещается при минимуме 3/8 символа, одна колонка = несколько дней.
- **Высота строк ПТД**: 1 ед ≈ 1,4 px при выводе кодом; подгонять под `Поле.Высота`, сжимать группы до ~0,4 масштаба, шапку не сжимать; полосы прокрутки — только если не влезло.
- **Замеры**: `ТекущаяУниверсальнаяДатаВМиллисекундах` + `Сообщить`; построение 16 строк 40–50 мс, 150 строк ~125 мс — задержки в ожидании, не в построении.
