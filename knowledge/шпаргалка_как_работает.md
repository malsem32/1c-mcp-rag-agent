# Шпаргалка: как устроен помощник

Простыми словами: **что модель «видит всегда»**, **что подгружается инструментами**, **куда класть правки**.

Папка знаний по умолчанию: `D:\rag_agent\knowledge`  
(можно сменить переменной окружения `RAG_KNOWLEDGE_DIR`).

---

## Два слоя

| Слой | Когда попадает к модели | Что это |
|------|-------------------------|---------|
| **A. System instructions** | Один раз при **старте** MCP (`python main.py`) | Текст `правила_агента.md` |
| **B. Tools (инструменты)** | Только если модель **вызваля tool** в этом чате | 1С, YAML, справка платформы, карта… |

Модель **не** читает всю папку `knowledge/` сама.  
Либо правила уже в system prompt, либо ответ tool’а пришёл в диалог.

---

## Слой A — всегда в контексте (старт MCP)

```
knowledge/правила_агента.md
        │
        ▼  get_agent_rules()   (при запуске main.py)
        │
        ▼  FastMCP(instructions=…)
        │
        ▼  LM Studio / клиент MCP  →  system prompt модели
```

| Файл | Подгружается как instructions? |
|------|--------------------------------|
| **правила_агента.md** | **Да** (основной текст) |
| карта_помощника.yaml | **Нет** (только tool `manager_help`) |
| словарь, YAML-справки, hbk | **Нет** |

В `правила_агента.md` подставляются плейсхолдеры:

| Плейсхолдер | Значение |
|-------------|----------|
| `{размер_контекста}` | из config (окно контекста) |
| `{ссылка_на_файлы}` | локальный HTTP Excel, обычно `http://127.0.0.1:8766` |

### После правки правил

1. Сохранить `правила_агента.md`  
2. **Перезапустить** `main.py` / переподключить MCP в LM Studio  

Иначе клиент держит **старый** `instructions` с момента connect.

## Слой B — только через инструменты

### Данные и объекты **вашей** 1С (HTTP)

| Tool | Зачем | Откуда данные |
|------|--------|----------------|
| `build_report` | Отчёт / список / «какие есть…» по фразе | 1С + словарь + поиск объектов |
| `resolve_object` | Найти full_name; 0→уточнить, много→options, 1→дальше | Метаданные 1С (+ синонимы из словаря) |
| `quick_find` | Короткий поиск объекта | то же, внутри ≈ resolve_object |
| `find_metadata` / `list_*` | Поиск/списки по классу | 1С |
| `get_object_structure` | Реквизиты / ТЧ / forms | 1С + dump |
| `describe_object` | Полное описание: реквизиты, ТЧ, формы, макеты, layout | 1С + dump XML |
| `describe_form` | Layout Form.xml: DataPath, element_types | dump |
| `resolve_business_fields` | Дата/сумма/… → реальные имена полей | 1С + **реквизиты_1с.yaml** |
| `execute_query` | ВЫБРАТЬ | 1С |
| `compare_periods` / `summarize_periods` | Сравнение периодов | 1С |
| `export_*` / `open_export` | Excel | локально + HTTP-раздача |
| `code_status` / `find_modules` / `search_code` / `module_outline` / `read_code` | Код конфигурации (BSL) | выгрузка `RAG_CODE_DIR`, только сниппеты (32k) |
| `test_connection` | Связь с 1С | 1С |

Имена объектов (**Документ.X**, **Справочник.Y**) **не зашиты** в код — только из ответа 1С / tools.

### Знания на диске (YAML / MD) — через tools

| Tool | Файлы knowledge |
|------|-----------------|
| `manager_help` | **карта_помощника.yaml** |
| `code_help` | **справка_по_коду.yaml** + статьи **справка_платформы/** |
| `query_syntax_help` | **синтаксис_запросов.yaml** + при необходимости hbk |
| `query_examples` | **примеры_запросов.yaml** |
| `knowledge_search` | md/yaml заметок + **справка_платформы** (индекс) |
| `reload_knowledge` | сброс кэша Python (не заменяет рестарт MCP для rules) |

### Словарь (без отдельного tool)

**словарь_бизнеса.yaml** читает **код** внутри:

- `build_report` / intent  
- `resolve_object` (синонимы к поисковой фразе)  

Модель файл целиком не видит — только эффект на поиск/ранжирование.

## Справка платформы (синтакс-помощник)

```
info/*.hbk
   → scripts/unpack_hbk.py
   → clean / drop_stub / rebuild_help_index
   → knowledge/справка_платформы/
         индекс.json
         синтаксис_помощник/…
         язык_запросов/…
         встроенный_язык/…
```

| Как попадает к модели | Tool |
|----------------------|------|
| Поиск по индексу + текст статьи | **`knowledge_search`** |
| То же + короткая шпаргалка YAML | **`code_help`** |

**Не** грузится целиком в system prompt (тысячи файлов).  
Пустые карточки («только имя») в индекс не кладём.

Обновление индекса:

```
python scripts/rebuild_help_index.py
```

## Карта: «вопрос → куда»

| Вопрос пользователя | Куда идти |
|---------------------|-----------|
| Продажи / список / «какие есть…» / цифры | **`build_report`** (данные 1С) |
| Неясно какой объект; list по одному классу пустой | **`resolve_object`** |
| Синтаксис, циклы, методы, «расскажи про… в 1С» | **`knowledge_search`** / **`code_help`** |
| Только ВЫБРАТЬ / ГДЕ / СУММА | **`query_syntax_help`** (+ search) |
| Шаблон запроса под уже известный full_name | **`query_examples`** |
| Какой tool взять | **`manager_help`** |
| Excel | только если просили файл → export tools |

## Кэш

Чтение knowledge в Python часто через `@lru_cache`:

| Действие | Эффект |
|----------|--------|
| `reload_knowledge` (tool) | Сброс кэша YAML/индекса/правил **в процессе** |
| Рестарт `main.py` | Новый system `instructions` + чистый процесс |

После правки **только** словаря/YAML: иногда хватает `reload_knowledge`.  
После правки **правила_агента.md**: нужен **рестарт MCP**.

## Что править человеку

| Хочу… | Файл |
|-------|------|
| Как модель должна себя вести | **правила_агента.md** → рестарт MCP |
| Шаги «когда что вызывать» (по tool) | **карта_помощника.yaml** |
| Синонимы: оплата/платёж/… | **словарь_бизнеса.yaml** |
| Как искать «сумму», «дату» в реквизитах | **реквизиты_1с.yaml** |
| Короткие шпаргалки BSL | **справка_по_коду.yaml** |
| Язык запросов (кратко) | **синтаксис_запросов.yaml** |
| Шаблоны ВЫБРАТЬ | **примеры_запросов.yaml** |
| Заметки про **нашу** базу | **база/**, **заметки/** |
| Полная справка платформы | hbk → scripts → **справка_платформы/** |

**Не** править код, чтобы «добавить имя Документ.Реализация» — имена только из 1С.

## Схема одним взглядом

```
┌──────────────────────────────────────────────────────────┐
│  СТАРТ MCP                                               │
│  правила_агента.md  ──►  system instructions  ──► модель │
│  docstring tools в main.py ──► список tools MCP          │
└──────────────────────────────────────────────────────────┘
                         │
                         │ каждый ответ (tool calls)
                         ▼
┌──────────────┐   ┌──────────────┐   ┌────────────────────┐
│ 1С (HTTP)    │   │ YAML/MD      │   │ справка_платформы  │
│ отчёты       │   │ code_help    │   │ knowledge_search   │
│ resolve_*    │   │ manager_help │   │ code_help (+hbk)   │
│ structure    │   │ query_*      │   │ индекс.json        │
└──────────────┘   └──────────────┘   └────────────────────┘
```

## Частые ошибки

1. **«В базе нет X»** после пустого `list_document_types`  
   → объект мог быть в **другом классе**. Нужен `resolve_object` / `build_report`, не один list.

2. **Синтаксис FOR/WHILE**  
   → модель ответила из памяти. Нужны `knowledge_search` / `code_help`, BSL по-русски.

3. **Правила не применились**  
   → не перезапустили MCP после правки `правила_агента.md`.

4. **Выдуманный Документ.ИмяДокумента**  
   → запрещено правилами; full_name только из tools / 1С.
