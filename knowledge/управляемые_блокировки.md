# Управляемые блокировки — как помощник агента

## Роль агента

Помощник **разработчику** при переходе на **управляемый** режим блокировок данных:

1. Где в проведении/записи конкурентный доступ (движения, остатки, расчёты).
2. Какие **пространства** блокировать (имена из **этой** CF: movements + structure).
3. Какой **режим** (обычно **Исключительный** перед изменением остатков/расчётов).
4. **Шаблон BSL** (`БлокировкаДанных` → `Добавить` → `УстановитьЗначение` → `Заблокировать`).
5. Чеклист миграции (свойство конфигурации, транзакции, тесты, ТЖ).

Агент **не** подключает live wait-graph; после включения managed смотрите ТЖ `TLOCK`/`TTIMEOUT`.

## Tools

| Вопрос | Tool |
|--------|------|
| Куда ставить / что внедрить / исправить | **`recommend_managed_locks`** |
| Где уже есть блокировки в коде | **`analyze_locks`** |
| Какие регистры пишет документ | **`analyze_object_movements`** |
| Измерения регистра | **`get_object_structure`** |

## Типовой порядок работ

1. Выбрать документ (или сценарий): `resolve_object` / `full_name=Документ.X`.
2. `recommend_managed_locks(request=…, full_name=Документ.X)`.
3. По `recommendations[]`: space, mode, dimensions_suggest, action.
4. Вставить шаблон в `ОбработкаПроведения` (или точку записи) — подставить поля объекта.
5. Режим управления блокировкой данных у объекта/конфигурации → **Управляемый**.
6. Тест: два сеанса, одни измерения; при проблемах — ТЖ.

## Правила (платформа)

- Блокировать **минимум измерений**, не весь регистр.
- Один и тот же **порядок** пространств/измерений во всех модулях (меньше deadlock).
- Блокировка **внутри** транзакции, **до** чтения остатка, который потом пишете.
- Короткая транзакция: без UI, почты, долгих HTTP.
- `ДЛЯ ИЗМЕНЕНИЯ` в запросе — тоже блокировка на уровне СУБД; не смешивать хаотично.

## Чего не делать

- Не копировать `Документ.Реализация…` из другой базы — только metadata текущей.
- Не обещать «после правок никогда не будет ожиданий» без нагрузочного теста.
- Не путать **управляемые** блокировки 1С с **объектными** `ЗаблокироватьДанныеДляРедактирования` (формы) — оба могут понадобиться, но задачи разные.
