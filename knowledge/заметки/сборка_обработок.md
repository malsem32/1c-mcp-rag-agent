# Сборка внешних обработок (.epf)

Цель: собрать рабочую обработку с первого раза через `build_external_processing`; человек только проверяет.
Платформа 8.3.24, обычное приложение (обычные формы). Пометки: **[клиент]** — запускалось в живом клиенте 1С;
**[выгрузка]** — взято из Form.bin конфигурации или справки платформы, в клиенте не пробовали.

## Что собирает tool

- Основная форма «Форма»: надпись + поле на каждый реквизит, таблица на каждую ТЧ, кнопки «Выполнить» / «Закрыть».
  Обработчик «Выполнить» в модуле формы: `Процедура ОсновныеДействияФормыОсновныеДействияФормыВыполнить(Кнопка)`.
  Без `form_module` кнопка вызывает `ВыполнитьОбработку()` модуля обработки (должна быть `Экспорт`).
- `extra_forms: [{name, title, module}]` — дополнительные формы без полей.
- **События формы назначаются по имени процедуры** в модуле формы. Без назначения процедура с таким именем не вызывается
  (**[клиент]**: `ПриОткрытии` не срабатывал, пока сборщик не стал прописывать событие в макете формы).
  **[клиент]** работает: `ПриОткрытии`. **[выгрузка]** сборщик умеет и остальные (`ПередОткрытием`, `ПередЗакрытием`, `ПриЗакрытии`,
  `ОбработкаВыбора`, `ОбработкаОповещения`, `ПриПовторномОткрытии`, `ОбновлениеОтображения`, `ВнешнееСобытие`, …), но в клиенте их не гоняли;
  параметры у части событий свои (например `ПередОткрытием(Отказ, СтандартнаяОбработка)`) — сверяй по справке платформы.
- **События полей ввода — по имени процедуры** `<ИмяРеквизита><Событие>(Элемент)`, например `ПодразделениеПриИзменении(Элемент)`.
  **[клиент]** работает: `ПриИзменении` (смена поля открывает/перестраивает диаграмму без кнопки).
  **[выгрузка]** сборщик умеет также `НачалоВыбораИзСписка`, `НачалоВыбора`, `Очистка`, `Регулирование`, `Открытие`, `ОбработкаВыбора`,
  `ОкончаниеВводаТекста`, `АвтоПодборТекста` — в клиенте не проверяли, параметры сверяй по справке.
  События таблиц, надписей и кнопок не назначаются (кнопка «Выполнить» — как есть).
- Реквизиты обработки доступны в модуле обработки и во всех формах по имени.
- Ссылочные типы: `СправочникСсылка.Имя`, `ДокументСсылка.Имя`, … — имя объекта только из tools (describe_object / resolve_object).

## Как принято у владельца

1. **Общая логика — в модуле обработки** (параметр `module`): запрос, расчёт, заполнение результата — экспортными
   процедурами. В модулях форм только интерфейс (создать элемент, вызвать процедуру модуля, заголовок).
2. **Две формы**:
   - «Форма» — поля параметров для ручного теста; «Выполнить» открывает форму результата;
   - форма результата (`extra_forms`) — только результат, строится в её `ПриОткрытии`, кнопки скрыты.
3. **Вызов из кода** (так открывают в рабочих конфигурациях):
   ```bsl
   Обработка = ВнешниеОбработки.Создать(ПутьКФайлу);
   Обработка.Подразделение = …;  Обработка.ДатаНач = …;  Обработка.ДатаКон = …;
   Обработка.ПолучитьФорму("ФормаДиаграммы").Открыть();
   ```
4. **Без модальных окон** (`Предупреждение`, `Вопрос`, `ОткрытьМодально`, `Ввести…`) — блокируют интерфейс.
   Сообщения, в т.ч. «нет данных», — только `Сообщить()`. Tool предупреждает о модальных вызовах в `bsl_warnings`.

## Шаблон

Модуль обработки:
```bsl
Функция ПолучитьДанные() Экспорт … КонецФункции          // запрос по реквизитам обработки
Процедура ЗаполнитьРезультат(Элемент) Экспорт … КонецПроцедуры
```
Основная форма (кнопка и смена полей делают одно и то же):
```bsl
Процедура ПоказатьРезультат()
	Форма = ПолучитьФорму("ФормаРезультата");
	Если Форма.Открыта() Тогда
		Форма.Перестроить();   // у уже открытой формы ПриОткрытии заново не вызовется — перестраиваем вручную
	Иначе
		Форма.Открыть();
	КонецЕсли;
КонецПроцедуры

Процедура ОсновныеДействияФормыОсновныеДействияФормыВыполнить(Кнопка)
	ПоказатьРезультат();
КонецПроцедуры

Процедура ПодразделениеПриИзменении(Элемент)   // <ИмяРеквизита>ПриИзменении
	ПоказатьРезультат();
КонецПроцедуры
```
В форме результата: `Процедура Перестроить() Экспорт  ЗаполнитьРезультат(Результат); КонецПроцедуры`.
Форма результата:
```bsl
Перем Результат;

Процедура ПриОткрытии()
	Если Результат = Неопределено Тогда   // объект формы живёт после закрытия: второй Добавить() упадёт
		ЭлементыФормы.ОсновныеДействияФормы.Видимость = Ложь;
		Результат = ЭлементыФормы.Добавить(Тип("ДиаграммаГанта"), "Результат", Истина);
		Результат.Лево = 4;  Результат.Верх = 4;
		Результат.Ширина = Ширина - 30;  Результат.Высота = Высота - 50;   // подобрано на форме 760x470: размер формы с рамкой, клиентская часть меньше
		Результат.УстановитьПривязку(ГраницаЭлементаУправления.Право, ЭтаФорма.Панель, ГраницаЭлементаУправления.Право);
		Результат.УстановитьПривязку(ГраницаЭлементаУправления.Низ, ЭтаФорма.Панель, ГраницаЭлементаУправления.Низ);
	КонецЕсли;
	ЗаполнитьРезультат(Результат);
КонецПроцедуры
```

## Элементы палитры (`controls`)

**[клиент]** (форма открывается, элементы заполняются из `ПриОткрытии`; срабатывают Нажатие кнопки, ПриИзменении флажка, полосы регулирования и календаря, Выбор табличного поля; остальные события — по выгрузке) — все 25 типов палитры обычной формы:
Кнопка, Надпись, ПолеВвода, Флажок, Переключатель, ПолеВыбора, ПолеСписка, ТабличноеПоле, ПолеТабличногоДокумента,
ПолеТекстовогоДокумента, ПолеHTMLДокумента, ПолеКалендаря, ПолеКартинки, Диаграмма, ДиаграммаГанта, СводнаяДиаграмма,
Дендрограмма, ПолеГрафическойСхемы, ПолеГеографическойСхемы, Индикатор, ПолосаРегулирования, Панель, РамкаГруппы,
Разделитель, КоманднаяПанель.

- `controls: [{type, name, title, left, top, width, height, value_type}]` — у основной формы (ставятся под полями реквизитов и
  таблицами ТЧ), у доп. формы — `extra_forms: [{name, title, module, controls, width}]`. Без `top` — друг под другом,
  без `width` — во всю ширину; `form_width` — ширина основной формы.
- Элементы **не привязаны** к реквизитам: в модуле формы `ЭлементыФормы.<Имя>`, значение — `.Значение`;
  заполнять в `ПриОткрытии` (список выбора, `ТабличноеПоле.Значение = ТЗ; СоздатьКолонки()`, `ПолеHTMLДокумента.УстановитьТекст(…)`).
  Поле ввода реквизита — по-прежнему через `attributes`.
- События — по имени процедуры модуля формы `<ИмяЭлемента><Событие>`: Кнопка/Надпись/ПолеКартинки — `Нажатие(Элемент)`;
  Флажок, Переключатель, ПолеВыбора, ПолосаРегулирования, ПолеКалендаря — `ПриИзменении(Элемент)`;
  ТабличноеПоле — `Выбор`, `ПриАктивизацииСтроки`, `ПриВыводеСтроки`, `ПередУдалением` …;
  ПолеТабличногоДокумента — `ОбработкаРасшифровки`, `ПриАктивизацииОбласти`; Панель — `ПриСменеСтраницы`;
  ПолеСписка — `Выбор`, `ПриИзмененииФлажка`. Параметры процедур сверяй по справке платформы.
- Не умеет: элементы внутри Панели (страницы), кнопки командной панели, события диаграмм — их добавлять кодом.

## Макеты (печатные формы) — `templates`

**[выгрузка]** (платформа читает собранный макет и выгружает в XML, всё совпадает; в клиенте ещё не открывали): табличный документ-макет со стилями, объединением ячеек, параметрами и именованными областями — без запуска 1С.

```json
templates: [{name: "Накладная", columns: [30, 200, 60, 80],
  styles: {заголовок: {bold: true, border: "all", fill: "#DDDDDD", align: "center"}, число: {border: "all", align: "right"}},
  rows: [ {cells: [{text: "Накладная № [Номер] от [Дата]", colspan: 4, bold: true, align: "center"}]},
          {height: 24, cells: [{text: "№", style: "заголовок"}, {text: "Товар", style: "заголовок"}, …]},
          {cells: [{param: "НомерСтроки", style: "число"}, {param: "Товар", detail: "ТоварСсылка"}, …]} ],
  areas: [{name: "Шапка", rows: [0, 1]}, {name: "Строка", rows: [2, 2]}] }]
```

- Колонки/строки с 0. Ячейка: `text` (со `[Имя]` — шаблон, подставляется `Параметры.Имя`), `param` (параметр области), `detail` (расшифровка, только с `param`), `colspan`/`rowspan`, `col` (явная колонка), `style` + любые свойства стиля прямо в ячейке (`font`, `size`, `bold`, `italic`, `underline`, `strike`, `align`, `valign`, `wrap`, `border` (`all` или `left,top`), `line` (solid/dotted/double/dashed/thick_dashed/large_dashed), `border_width`, `fill`/`color`/`border_color` `#RRGGBB`).
- Области — для `ПолучитьОбласть("Имя")`: `rows:[с,по]`, `cols:[с,по]`, `rect:[стр1,кол1,стр2,кол2]` (границы включительно).
- В коде (модуль обработки, процедура `Экспорт`):
```bsl
Макет = ПолучитьМакет("Накладная");
Обл = Макет.ПолучитьОбласть("Строка");
Обл.Параметры.Товар = Стр.Товар;
ТабДок.Вывести(Обл);   // ТабДок — ЭлементыФормы.<ПолеТабличногоДокумента>; перед выводом ТабДок.Очистить()
```
- Единицы (измерено по скриншоту владельца): ширина 1 ед ≈ 0,87 px (колонка 72 ≈ 63 px, 150 ≈ 131 px); высота строки 1 ед ≈ 0,38 px (строка 10 pt ≈ 40 ед). **Высоту строки не задавай** — без `height` строка растёт по тексту, в т.ч. с переносом слов (проверено); `height` < 40 схлопывает строку в линию — нужен только для отступов и фиксированных строк. Не умеет: числовые форматы, отступы, картинки, печатные настройки, группировки строк.

- Создание кодом (`ЭлементыФормы.Добавить(Тип("…"), "Имя", Истина)`, один раз) по-прежнему работает (см. шаблон выше).

## График отпусков / загрузки таблицей (дизайн владельца: тонкие полосы план/факт, «сегодня», группы)

Если нужен вид «как на макете» (группы-подразделения с числом людей, у каждого работника серая полоса плана и цветная полоса факта
с числом дней, красная линия «сегодня», легенда плашками), `ДиаграммаГанта` не подходит — строить в **поле табличного документа**
(**[выгрузка]** по справке платформы; в клиенте на момент записи не проверялось, см. журнал скилла epf-build). Приёмы:
- Поле: `Поле = ЭлементыФормы.Добавить(Тип("ПолеТабличногоДокумента"), "График", Истина)` один раз; методы табличного документа
  (`Очистить`, `Область`) вызываются у самого поля. Скрыть `ОтображатьСетку`, `ОтображатьЗаголовки`.
- Колонка на каждый день периода. Полоса = объединённые ячейки одной строки с `ЦветФона`; число дней — текст в объединённой ячейке.
  `Область(r1, c1, r2, c2).Объединить()`. Колонки/строки целиком: `Область(, c1, , c2)` / `Область(r, , r)` (пропуск параметров).
- Высота тонких строк-полос ~9 пт (`ВысотаСтроки` в пунктах), ширина колонки-дня ~0.4–4 (`ШиринаКолонки` в «средних символах»).
- Линия «сегодня»: закрасить колонку `ЦветФона`; полосы, пересекающие эту колонку, делить на две части вокруг неё.
- Границы: `Область.ГраницаСнизу = Новый Линия(ТипЛинииЯчейкиТабличногоДокумента.ЧастыйПунктир, 1)`, цвет всех границ области — `ЦветРамки`.
  Толщина линии ячейки может быть только 1.
- Объединять можно каждую область один раз: перекрывающиеся записи (дубли плана) предварительно склеивать в коде, иначе ошибка выполнения.
- Общая логика (запрос, склейка, раскладка строк, вывод) — в модуле обработки одной процедурой `ЗаполнитьГрафик(Поле)`, форма только создаёт поле.
- Проверять без клиента: `python scripts/_bsl_syntax_check.py` и имитация `exports/gantt_src/sim_check.py`.

## Диаграмма Ганта (обычная форма)

```bsl
Диаграмма.Обновление = Ложь;
Диаграмма.Очистить();
Диаграмма.АвтоОпределениеПолногоИнтервала = Ложь;
Диаграмма.УстановитьПолныйИнтервал(НачалоДня(ДатаНач), КонецДня(ДатаКон));
СерияПлан = Диаграмма.УстановитьСерию("План"); СерияПлан.Цвет = Новый Цвет(120, 170, 230);
Для Каждого Стр Из Данные Цикл
	Диаграмма.УстановитьТочку(Стр.Группа);                     // верхний уровень
	Точка = Диаграмма.УстановитьТочку(Стр.Элемент, Стр.Группа); // второй параметр — ЗНАЧЕНИЕ родителя
	Интервал = Диаграмма.ПолучитьЗначение(Точка, СерияПлан).Добавить();
	Интервал.Начало = Стр.Начало;
	Интервал.Конец = КонецДня(Стр.Окончание);
КонецЦикла;
Диаграмма.Обновление = Истина;
Диаграмма.ПоказатьУровеньТочек(0);   // 0 = раскрыть все уровни; вызывали ПОСЛЕ Обновление = Истина (так в клиенте раскрылось)
```

- Шкала времени: у созданной кодом диаграммы в шкале один элемент «День» — на интервале в год пусто.
  При создании добавить месяцы: `Шкала = Диаграмма.ОбластьПостроения.ШкалаВремени; Шкала.Положение = ПоложениеШкалыВремени.Верх;
  Э = Шкала.Элементы.Добавить(); Э.Единица = ТипЕдиницыШкалыВремени.Месяц; Э.Формат = "ДФ='MMM yy'";`
  (`Диаграмма.ШкалаВремени` — такого свойства нет, только через `ОбластьПостроения`).
- Разделить людей цветом: у интервала есть `Интервал.Цвет` (явный цвет перекрывает цвет серии), у точки — `Точка.ЦветТекста`
  (имя тем же цветом). Палитра ~10 насыщенных цветов, работник берёт цвет по порядку появления (соседи всегда разные),
  план = тот же цвет, смешанный с белым на 55%. Серии в легенде сделать нейтральными (план светло-серый, факт тёмно-серый),
  иначе легенда врёт. Пример — `exports/gantt_src/show.bsl` (`ПалитраРаботников`, `СмешатьСБелым`).
- Раздробленные записи склеивать в коде до вывода: сортировка по (группа, элемент, серия, начало), следующая запись входит в предыдущую,
  если `НачалоДня(Начало) <= НачалоДня(ПредыдущийКонец) + 86400` (пересечение или встык). **[клиент]** на тестовых данных работает;
  на реальной базе владельца не проверено — предположение, что «зазубрины» на полосах были записями встык, ещё не подтверждено им.
  Записи с пропуском в целый день не склеиваются.
- Легенда: по умолчанию справа и занимает широкую колонку. Вариант `ОбластьЛегенды.Расположение = РасположениеЛегендыДиаграммы.Верх`
  в наших тестах работал **[клиент]**, но на рабочей базе владельца справа осталось пустое поле, а легенда легла поверх шкалы времени
  (причину не выяснили, у себя не воспроизвелось). Надёжнее задать границы явно **[клиент]**: доли 0..1 от элемента, платформа от 8.3.12:
  `Л = Диаграмма.ОбластьЛегенды; Л.Расположение = РасположениеЛегендыДиаграммы.УказываетсяРасположение; Л.Лево = 0.48; Л.Верх = 0; Л.Право = 0.56; Л.Низ = 0.055; Л.Прокрутка = Ложь;`
  (записи легенды прижимаются к левому краю своей области, поэтому для центрирования область сделана узкой и по центру: 0.48..0.56; на всю ширину 0..1 легенда стоит слева.)
  `П = Диаграмма.ОбластьПостроения; П.Расположение = РасположениеОбластиПостроенияДиаграммы.УказываетсяРасположение; П.Лево = 0; П.Верх = 0.055; П.Право = 1; П.Низ = 1;`
  Высота полосы легенды — доля высоты: на очень высоких окнах она шире (записи «План/Факт» раздвигаются), на низких (<400 px) может не вместить две строки.
  Размер формы по умолчанию 1000x640, чтобы полоса вмещала легенду.
- Подписи серий справа от полос (`ОтображениеТекстаЗначения = ОтображениеТекстаЗначенияДиаграммыГанта.Право` +
  `Значение.Текст = "План"`) работают, но у правого края шкалы обрезаются; владелец от них отказался — не добавлять без просьбы.
- `Интервал.Текст` с датами не задавали: на коротких полосах текст переносится по словам и нечитаем.
- Каждая серия — своя подстрока точки (План и Факт друг под другом) — удобно сравнивать.

## Внешний отчёт (.erf)

Тот же tool: `build_external_processing(kind="report", name, synonym, query, parameters, resources, group_by, order)`.
Собирается отчёт на СКД со стандартной формой (кнопки «Сформировать», «Настройки…», «Конструктор настроек…»); модуль формы пуст,
платформа сама строит результат. Модуль объекта (`module`) — необязателен (например, `ПриКомпоновкеРезультата`).

- `query` — текст запроса. В пакете результатом считается последний `ВЫБРАТЬ` без `ПОМЕСТИТЬ`; у каждой колонки нужен псевдоним `КАК`
  (`*` нельзя). Имена объектов конфигурации — только из tools (`describe_object`, `resolve_object`).
- `parameters` — по одному на КАЖДЫЙ `&Параметр` запроса: `{name, title, type, value}`. Тип: `Дата`, `ДатаВремя`, `Строка(N)`, `Число(N,M)`,
  `Булево`, `СправочникСсылка.Имя` и т.п. (значение ссылочного параметра не задаётся — пользователь выберет в настройках).
  Значение даты: `2026-01-01`, `01.01.2026` или `Начало месяца` / `Начало года` / `Начало следующего месяца` …
- `resources` — суммируемые колонки (`["Сумма"]` или `[{"name":"Количество","aggregate":"Максимум"}]`); `group_by` — колонки группировки
  по порядку вложенности (пусто — плоский список); `order` — `["Сумма Убыв"]`; `fields` — свои заголовки колонок `[{name,title}]`.
- Пример: `query = "ВЫБРАТЬ Т.Склад КАК Склад, Т.Номенклатура КАК Номенклатура, Т.КоличествоОстаток КАК Количество ИЗ РегистрНакопления.<Регистр>.Остатки(&НаДату) КАК Т"`,
  `parameters = [{"name":"НаДату","title":"На дату","type":"Дата","value":"Начало следующего месяца"}]`, `resources = ["Количество"]`, `group_by = ["Склад"]`.
- Несколько наборов: `datasets=[{name, query, fields?}]` вместо `query`. Без `links` наборы объединяются (одноимённые колонки сливаются);
  связь — `links=[{source, dest, source_expression, dest_expression}]` (имена наборов и колонки). Параметры описываются общим списком.
- Вычисляемые поля: `calculated_fields=[{name, expression, title}]`, выражение на языке выражений СКД (`Сумма - Оплачено`,
  `Выбор Когда … Тогда … Иначе … Конец`); имя не должно совпадать с колонкой запроса; их можно ставить в `resources`, `group_by`, `order`.
- Отборы по умолчанию: `filters=[{field, op, value, use}]`; field — колонка запроса или вычисляемое поле; op: `=` `<>` `>` `>=` `<` `<=` `содержит` `не содержит` `начинается с` `заполнено` `не заполнено`; value — строка/число/Истина/дата (ссылочные не задаём); `use:false` — отбор есть, но выключен.
- Реквизиты и ТЧ самого отчёта: `attributes=[{name,synonym,type}]`, `tabular_sections=[{name,synonym,columns:[…]}]` — доступны в модуле отчёта (`ПриКомпоновкеРезультата` и др.), на стандартной форме отчёта полей не создаются.
- Своя форма отчёта: `form_fields=true` — над полем «Результат» появляются поля ввода реквизитов и таблицы ТЧ; `controls` (палитра как у обработки), `form_module` (процедуры по именам: `<Реквизит>ПриИзменении`, `<Кнопка>Нажатие`, `ПриОткрытии`), `form_width`, `extra_forms` (открывать из модуля отчёта `ПолучитьФорму("Имя").Открыть()`). Кнопки «Сформировать/Настройки…» остаются стандартными.
- Настройки варианта (всё необязательно, ключи верхнего уровня = основной вариант; те же ключи в `variants=[{name,title,…}]` для других вариантов):
  `structure=[{group:[поля], select, order, filters, output, items:[вложенные]}, {table:{rows:[поля цепочкой], columns:[поля]}}, {chart:{points:[…], series:[…], output:{ТипДиаграммы}}}]`,
  `appearance=[{fields, filters:[{field,op,value}], text_color, back_color (#RRGGBB или «красный»), bold, italic, underline, format, text}]`,
  `user_fields=[{name,title,expression} | {name,title,cases:[{filters,value}]}]` (путь `UserFields.Имя`, попадают в выбранные поля), `select=[поля]`,
  `output={ВыводитьЗаголовок|ВыводитьОтбор|ВыводитьПараметрыДанных: Auto|Output|DontOutput, РасположениеИтогов|ВертикальноеРасположениеОбщихИтогов|ГоризонтальноеРасположениеОбщихИтогов: Auto|None|Begin|End|BeginAndEnd, ТипЗаголовкаПолей: Full|Short, РасположениеПолейГруппировки, РасположениеРеквизитов, МакетОформления, Заголовок}`.
- Отборы: `filters=[{field, op, value|values, use, view}, {group:И|ИЛИ|НЕ, items:[…]}]`; op: = <> > >= < <= содержит «не содержит» «начинается с» подобно заполнено «не заполнено» «в списке» «не в списке» «в группе»; значение-ссылка — строкой «Справочник.Контрагенты.ПустаяСсылка» (или «Перечисление.Имя.Значение»; объект проверяется по каталогу базы), сравнение с другим полем — `{field: Имя}`; «в списке» без values — список заполнит пользователь. Ссылочное значение параметра — `parameters=[{name, type: СправочникСсылка.Контрагенты, value: "Справочник.Контрагенты.ПустаяСсылка"}]`.
- Наборы данных: `datasets=[{name, query}, {name, object, fields:[{name,title,type}]}, {name, union:[{name,query}|{name,object,fields}, …]}]`. Набор-объект — внешние данные: в модуле отчёта `ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)` с `СтандартнаяОбработка = Ложь`, таблицу значений передать так: `КМ = Новый КомпоновщикМакетаКомпоновкиДанных; Макет = КМ.Выполнить(СхемаКомпоновкиДанных, КомпоновщикНастроек.Настройки, ДанныеРасшифровки); ПКД = Новый ПроцессорКомпоновкиДанных; ПКД.Инициализировать(Макет, Новый Структура("<object>", ТЗ), ДанныеРасшифровки); ПВ = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент; ПВ.УстановитьДокумент(ДокументРезультат); ПВ.Вывести(ПКД)`. Таблицы внешних источников данных 1С — прямо в тексте запроса (`ИЗ ВнешнийИсточникДанных.<Имя>.Таблица.<Имя>`).
- Диаграмма: `structure=[{chart:{points, series, select:[ресурсы], output:{ТипДиаграммы: Гистограмма|«Гистограмма объёмная»|Круговая|«Круговая объёмная»|График|Область|…, "ТипДиаграммы.ВидПодписей": Значение|Процент|«Значение и процент»…, "ТипДиаграммы.ЦветФона": "#RRGGBB", "ТипДиаграммы.Шрифт": {font:{bold,size,name}}, "ТипДиаграммы.МинимальноеЗначение": 0}}}]`. Если платформа какой-то параметр не знает — в ответе `warnings` со списком отброшенных.
- Макеты: числовой формат ячейки — `numfmt: "ЧЦ=15; ЧДЦ=2; ЧГ=3,0"` в стиле; картинка — `drawings:[{file|base64, row, col, rows, cols, size: proportional|stretch|real, offset:[4 числа]}]` (PNG/JPEG/GIF/BMP; высоту строки под картинку задать `height`).
- Макеты оформления: `templates=[…]` как у обработки (`ПолучитьМакет("Имя").ПолучитьОбласть("Область")` из модуля отчёта). Варианты (`variants`) в обычной форме отчёта выбираются из подменю панели — сборщик добавляет его сам (`Вариант_<Имя>`), после нажатия — «Сформировать»; пункты собираются в подменю «Вариант отчёта ▾». Свои подменю: `bar_menus=[{name,title,items:[{name,title,handler}]}]`. Кнопки командной панели отчёта: `bar_buttons=[{name,title,handler}]`, процедура `<name>Нажатие(Кнопка)` в `form_module`.
- Открывать: Файл → Открыть в клиенте 1С (обычное приложение); параметры и состав полей — «Настройки…».

## Чего сборщик не умеет

Макеты с картинками и числовыми форматами, управляемые формы, привязка элементов палитры к реквизитам (кроме полей ввода и ТЧ),
элементы внутри Панели, кнопки командной панели, события диаграмм и таблиц ТЧ. Отчёт `.erf`: свои макеты оформления,
макеты оформления отчёта, отказ от стандартной командной панели, группы отборов И/ИЛИ и ссылочные значения отборов.

## Режим совместимости
В BSL внешней обработки нельзя использовать функции новее режима совместимости конфигурации (у владельца Version8_2_16): например СтрРазделить, СтрСоединить, СтрНайти (8.3.x) недоступны — разбирать строки вручную (Найти/Сред/Лев). Проверка: `_bsl_syntax_check.py --compat 8.2.16`.
