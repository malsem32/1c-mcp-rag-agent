Этот файл рассчитан на человека, который **не программист** (или программист, но не в Python/Docker/AI).  
Цель: **понять, что происходит**, **что куда нажимать**, **какой параметр за что отвечает**.

Файл лежит здесь: `D:\rag_agent\ИНСТРУКЦИЯ.md`

# Часть A. Простыми словами: что это вообще

## A1. Что вы получаете в итоге

Вы сможете **спросить на русском**, например:

- «Сколько реализаций за январь 2015?» (имена объектов агент ищет в **вашей** базе)
- «По каким регистрам проводится документ …?» (укажите разговорно или full_name из metadata)
- «Почему не заполняется поле …?»
- «Как в запросе 1С написать соединение?»

и получить ответ **по вашей базе 1С** и **по коду вашей конфигурации**, а не «из головы» нейросети.  
Имена `Документ.X` / регистров **не зашиты** в код агента — после смены CF достаточно dump + index + `http.base_url`.

## A2. Из каких «деталей» состоит система

Представьте **секретаря**, у которого есть:

| Деталь | Аналогия | В проекте |
|--------|----------|-----------|
| **Мозг** | умеет думать и писать текст | **LLM** (языковая модель: ChatGPT-подобная) |
| **Телефон в бухгалтерию** | спросить живые данные из базы | **HTTP-сервис 1С** (`hs/ai`) |
| **Картотека с кодом** | быстро найти кусок модуля / справку | **Qdrant** (поисковая база) |
| **Блокнот с правилами** | «как отвечать», «как у нас принято» | папка **`knowledge/`** |
| **Программа-секретарь** | решает, кому звонить | **`agent.py`** или **`main.py`** |

Без **телефона (1С)** — не будет живых отчётов.  
Без **картотеки (Qdrant)** — не будет ответов по коду и синтаксису.  
Без **мозга (LLM)** — некому формулировать ответ и выбирать инструменты.  
Без **секретаря (agent)** — всё это не связано.

## A3. Что такое RAG (одной фразой)

**RAG** = «сначала **найти** нужные куски (код, справку, данные), потом **ответить**».  
Модель **не обязана помнить** вашу конфигурацию (УТ/УПП/кастом) — она **смотрит** в Qdrant и в 1С через инструменты.

## A4. Два разных «мира» 1С — не путайте

| Мир | Что это | Как попадает к агенту |
|-----|---------|------------------------|
| **Данные** (документы, остатки, суммы) | Живая информационная база | Через HTTP `…/hs/ai` **в момент вопроса** |
| **Код** (модули, запросы в BSL) | Текст программ конфигурации | Через **выгрузку файлов** → нарезка → **Qdrant** (заранее, долго) |

Платформа 1С **не отдаёт** текст модулей по обычному HTTP API.  
Поэтому код нужно **один раз выгрузить** из конфигуратора и **проиндексировать**.

# Часть B. Что должно быть установлено

## B1. Список

| № | Программа | Зачем обычным языком | Без неё… |
|---|-----------|----------------------|----------|
| 1 | **Windows 10/11** | Среда, в которой всё крутится | — |
| 2 | **Python 3.11+** | Язык, на котором написан агент | не запустятся `agent.py` и скрипты |
| 3 | **Docker Desktop** | «Коробка», внутри которой крутится Qdrant | нет нормального поиска по коду |
| 4 | **1С:Предприятие 8.3** + **веб-публикация** базы | Чтобы агент ходил в живые данные | нет отчётов и списков из ИБ |
| 5 | **Доступ к LLM** | Локально (LM Studio/Ollama) или облако (aigate, OpenAI…) | некому отвечать |

## B2. Docker — что это, зачем вам

**Docker** = способ запустить готовую программу (здесь — **Qdrant**) без ручной установки сервера.

**Qdrant** = база, которая умеет искать «по смыслу» и по тексту.  
В неё кладут **десятки тысяч кусков** кода и справки.

1. Скачайте Docker Desktop с официального сайта.
2. Установите, **перезагрузите** ПК если попросит.
3. Запустите Docker Desktop и **дождитесь** статуса вроде «Docker Desktop is running» (кит в трее).
4. **Пока Docker выключен — Qdrant мёртв**, агент код не найдёт.

## B3. Python — минимум

1. Установите Python с python.org (галочка **Add Python to PATH**).
2. Откройте **PowerShell**.
3. Проверка:

```powershell
python --version
```

Должно быть 3.11 или новее.

## Шаг 3. Подключить живую базу 1С (HTTP)

### 3.1. Зачем

Чтобы вопросы вроде «продажи за 2015» ходили **в реальную ИБ**, а не выдумывались.

### 3.2. Что нужно сделать в 1С (смысл)

1. В конфигурации или **расширении** есть (или создаётся) **HTTP-сервис**.
2. Имя сервиса обычно: **AI**.
3. **Корневой URL**: **`ai`**.
4. В модуль сервиса вставляется код из файла проекта:

```text
D:\rag_agent\onec_http\Module.bsl
```

5. База **опубликована** на веб-сервере (IIS / Apache от 1С — как у вас принято).
6. Получается адрес вида:

```text
http://ИМЯ_СЕРВЕРА/ИМЯ_ПУБЛИКАЦИИ/hs/ai
```

Пример из конфига по умолчанию:

```text
http://localhost/demobase/hs/ai
```

| Кусок URL | Значение |
|-----------|----------|
| `http://localhost` | компьютер, где крутится веб-сервер 1С |
| `demobase` | **имя публикации** (у вас может быть другим!) |
| `hs` | стандартный префикс HTTP-сервисов 1С |
| `ai` | корневой URL вашего сервиса |

### 3.3. Рекомендуемая настройка сервиса в конфигураторе

| Параметр | Что поставить | Простыми словами |
|----------|---------------|------------------|
| Имя HTTP-сервиса | `AI` | Внутреннее имя |
| Корневой URL | `ai` | Кусок адреса после `/hs/` |
| Шаблон URL | `*` (универсальный) **или** отдельные `/info`, `/list`… | Куда приходят запросы |
| Метод GET | обработчик `ОбработчикGET` | Чтение списков, info, search |
| Метод POST | обработчик `ОбработчикPOST` | Запросы `ВЫБРАТЬ`, журнал |

В `Module.bsl` в шапке есть комментарии — их можно сверять с конфигуратором.

### 3.4. Пользователь 1С

Создайте / выберите пользователя, **под которым агент будет ходить в базу**.

Ему нужны права:

- читать те справочники/документы/регистры, по которым ждут отчёты;
- для журнала регистрации — права на журнал;
- пароль (если basic-auth).

**Режим агента по умолчанию — только чтение** (`read_only: true`).  
Он не проводит документы и не пишет в базу через штатные tools.

### 3.5. Прописать адрес в `config.yaml`

Откройте `config.yaml` (Блокнот / VS Code / Notepad++).

Найдите блок `http:` и поставьте **свои** значения:

```yaml
backend: http

http:
  base_url: "http://localhost/ВАША_ПУБЛИКАЦИЯ/hs/ai"
  timeout: 60.0
  auth: basic
  username: "ИмяПользователяКакВ1С"
  password: ""
```

Пароль лучше **не** писать в yaml, а в `.env`:

```env
RAG_HTTP_PASSWORD=секрет
```

### 3.6. Проверка «телефон работает»

В браузере откройте:

```text
http://localhost/ВАША_ПУБЛИКАЦИЯ/hs/ai/info
```

(подставьте свой URL)

**Хорошо:** JSON / текст с информацией о конфигурации.  
**Плохо:** 404, 401, пустая страница, «сайт недоступен».

Также можно:

```powershell
python onec_http/test_http_api.py
```

## Шаг 4. Выгрузить код конфигурации

### 4.1. Зачем

Чтобы агент отвечал: «где в коде запрос», «какие движения», «цепочка вызовов».

### 4.2. Как

1. Откройте **Конфигуратор** вашей базы.
2. Меню примерно: **Конфигурация → Выгрузить конфигурацию в файлы**.
3. Укажите папку:

```text
D:\rag_agent\knowledge\код_конфигурации
```

(или выгрузите куда удобно и скопируйте содержимое сюда)

4. Дождитесь конца. Это **долго** и папка **огромная** (тысячи файлов).

### 4.3. Как понять, что выгрузка на месте

Внутри должны быть папки вроде:

- `Documents`
- `Catalogs`
- `CommonModules`
- `Reports`
- …

и файлы `Module.bsl`, `*.xml`.

**Важно:** имена папок **английские** (`Catalogs`, `Forms`) — так делает 1С. Это нормально.  
Русские названия объектов — внутри (`СоглашенияСКлиентами` и т.д.).

### 4.4. Агент в работе **не читает** эту папку напрямую

Он ищет по **индексу Qdrant**. Папка нужна для скриптов **prepare/index**.  
Если обновили конфигурацию — **снова** выгрузка + индексация.

## Шаг 7. Нарезать код и залить в Qdrant (самый долгий этап)

### 7.1. Два подшага

```
knowledge/код_конфигурации     (сырые файлы выгрузки)
        │
        │  prepare  — «порезать на куски»
        ▼
knowledge/qdrant_ready/*.jsonl (готовые куски текстом)
        │
        │  index  — «посчитать векторы и положить в Qdrant»
        ▼
Qdrant: коллекции onec_code + onec_help
```

### 7.2. Если JSONL уже есть

Посмотрите:

```text
knowledge\qdrant_ready\config_chunks.jsonl   ← код
knowledge\qdrant_ready\help_chunks.jsonl     ← справка
```

Если файлы большие (сотни MB у кода) — **prepare можно не гонять**, сразу index.

### 7.3. Prepare (если JSONL нет или обновили выгрузку)

```powershell
.\.venv\Scripts\Activate.ps1
python scripts/prepare_config_for_qdrant.py
```

**Сколько ждать:** порядка нескольких минут на большой базе.  
**Результат:** обновлённый `config_chunks.jsonl`.

### 7.4. Index — код + справка

```powershell
python scripts/index_qdrant.py --recreate
```

| Флаг | Смысл |
|------|--------|
| `--recreate` | **снести и создать коллекции заново** (нужно после Docker «с нуля», смены модели эмбеддингов, полной пересборки) |
| без флагов | код + help (по умолчанию) |
| `--code-only` | только код конфигурации |
| `--help-only` | только справка платформы |

**Или одной командой весь пайплайн:**

```powershell
python scripts/full_qdrant_pipeline.py
python scripts/full_qdrant_pipeline.py --skip-prepare   # JSONL уже есть
```

### 7.5. Сколько ждать index

На большой УТ (~80 тысяч кусков кода):

| Этап | Ориентир |
|------|----------|
| Код | **несколько часов** |
| Справка | **десятки минут** |

В консоли будут строки вроде `… upserted 1024`, `… upserted 2048` — число растёт = **всё ок**.  
**Не закрывайте** Docker и не убивайте окно, пока не закончится.

В dashboard Qdrant смотрите points у `onec_code` / `onec_help` — должны расти.

### 7.6. Проверка

```powershell
python scripts/verify_qdrant.py
python scripts/index_qdrant.py --status
```

Ожидаете: коллекции **не пустые**, поиск работает.

## Шаг 8. Настроить «мозг» — LLM

### 8.1. Что выбрать

и в yaml: `provider: openai` + имя модели.

2. В `config.yaml`:

```yaml
  provider: lmstudio
```

## D1. `backend` — способ связи с 1С


| Значение | Когда |

## D2. Блок `http` — адрес живой базы

```yaml

  timeout: 60.0
  auth: basic
  username: "Администратор"
  password: ""
```

| Параметр | За что отвечает | Как выбрать | Если ошибиться |
|----------|-----------------|-------------|----------------|
| **`base_url`** | Полный адрес HTTP-сервиса AI **без** слэша на конце методов | Скопировать из публикации 1С + `/hs/ai` | 404, connection refused, «не та база» |
| **`timeout`** | Сколько **секунд** ждать ответ 1С на один запрос | 30–120; тяжёлые запросы — больше | Обрыв на долгих `ВЫБРАТЬ` |
| **`auth`** | Нужна ли авторизация | `basic` — логин/пароль; `none` — если публикация без auth | 401 Unauthorized |
| **`username`** | Имя пользователя 1С | Как в списке пользователей ИБ (с пробелами/скобками — в кавычках) | 401 или «нет прав» |
| **`password`** | Пароль | Лучше пусто здесь + `RAG_HTTP_PASSWORD` в `.env` | 401; **не светите пароль в git** |

## D5. Блок `qdrant` — поисковая картотека

```yaml
qdrant:
  enabled: true
  mode: url
  path: "knowledge/qdrant_data"
  url: "http://localhost:6333"
  api_key: ""
  timeout: 120
  collection_code: "onec_code"
  collection_help: "onec_help"
  chunks_jsonl: "..."
  help_jsonl: "..."
  fallback_filesystem: false
  search_mode: hybrid
  lexical_scan_limit: 4000
```

| Параметр | За что отвечает | Рекомендация новичку |
|----------|-----------------|----------------------|
| **`enabled`** | Включён ли Qdrant вообще | `true` |
| **`mode`** | `url` = сервер (Docker); `local` = файлы на диске | **`url`** + Docker |
| **`path`** | Папка для **local**-режима | Не важно при `mode: url` |
| **`url`** | Адрес Qdrant | `http://localhost:6333` при Docker compose |
| **`api_key`** | Ключ, если Qdrant с паролем / Cloud | Пусто для локального Docker |
| **`timeout`** | Таймаут запросов к Qdrant (сек) | 120 на больших поисках |
| **`collection_code`** | Имя «ящика» с **кодом** | `onec_code` — не менять без причины |
| **`collection_help`** | Имя «ящика» со **справкой** | `onec_help` |
| **`chunks_jsonl` / `help_jsonl`** | Откуда index читает куски | Как в `paths` |
| **`fallback_filesystem`** | Если Qdrant пуст — искать ли файлы на диске | **`false`**: только индекс (как задумано) |
| **`search_mode`** | Как искать | **`hybrid`** = и точное слово, и «по смыслу» |
| | `semantic` | только смысл (хуже для точных имён процедур) |
| | `exact` | только точный текст |
| **`lexical_scan_limit`** | Сколько кандидатов смотреть в «текстовой» части hybrid | 4000 — баланс скорость/полнота |

Env: `QDRANT_API_KEY`.

**После смены `mode` на url и пустого Docker** — всегда `index_qdrant.py --recreate`.

## D6. Блок `embedding` — «как переводить текст в числа для поиска»

Перед поиском куски кода превращаются в **векторы** (наборы чисел).  
Одинаковая модель должна быть при **index** и при **поиске**.

```yaml
embedding:
  provider: fastembed
  model: "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
  batch_size: 64
  base_url: ""
  api_key: ""
```

| Параметр | За что отвечает | Новичку |
|----------|-----------------|---------|
| **`provider`** | `fastembed` = **локально** на вашем ПК; `openai` = через API | **`fastembed`** |
| **`model`** | Какая модель векторов | Не менять без нужды |
| **`batch_size`** | Сколько кусков обрабатывать за раз при index | 32–64; больше — быстрее, но больше RAM |
| **`vector_size`** | Размер вектора (если задаёте вручную) | Обычно не нужен |
| **`base_url` / `api_key`** | Для `provider: openai` | Пусто при fastembed |

**Критично:** сменили `model` → **обязательно** полный `--recreate` index. Иначе поиск «ломается» (векторы несовместимы).

| Параметр | За что отвечает | Простыми словами | Совет |
|----------|-----------------|------------------|-------|
| **`provider`** | Какой сервис модели | lmstudio / ollama / aigate / openai / … | Должен совпасть с тем, где у вас ключ/сервер |
| **`model`** | Имя конкретной модели | Как в кабинете провайдера / LM Studio | Неправильное имя → ошибка 404 от API |
| **`base_url`** | Адрес API | Пусто = взять из `providers` | Заполняйте, если свой прокси |
| **`api_key`** | Ключ | Пусто = из `.env` | Не коммитьте ключ в yaml |
| **`temperature`** | «Креативность» | 0 = сухо/строго; 1 = фантазии | Для 1С **0.0–0.2** |
| **`context_window`** | Сколько roughly «памяти» у модели | 32k сейчас; локально 64k/128k — поднять | Ставьте на 10% ниже max модели |
| **`max_tokens`** | Макс. длина **одного** ответа модели | Резерв из окна | 2048–4096 при 32k |
| **`max_tool_rounds`** | Сколько tool-раундов за 1 вопрос | Сложный вопрос = несколько поисков | 8–16 |

| **`history_max_messages`** | Soft-cap сообщений | Доп. к turns | 30–50 |
| **`history_max_turns`** | Сколько **вопросов пользователя** в окне | 1 ход = user+tools+answer | **6** при 32k |
| **`keep_recent_tool_full`** | Сколько последних tool JSON полные | Старые → summary ~700 симв. | 2 |
| **`old_tool_chars`** | Размер summary старого tool | | 500–900 |
| **`diary_*`** | Дневник сессии (факты без сырого JSON) | Follow-up «только Ассоль» | см. `session_memory.py` |

Также: **session memory** (`[память сессии]`) + `last_report` для фильтров follow-up. `/reset` чистит историю и память.

# Часть G. Как «думает» агент (чтобы не удивляться)

1. Вы пишете вопрос.
2. **LLM** решает: «нужны данные / код / справка».
3. Вызывает **tool** (поиск, запрос, отчёт…).
4. Tool ходит в **1С** или **Qdrant** или читает **yaml**.
5. Результат **обрезается** (`tool_result_max_chars`), возвращается модели.
6. Модель может вызвать tool **ещё раз** (до `max_tool_rounds`).
7. Пишет вам ответ по-русски.

Поэтому:

- «Галлюцинации» объектов → плохо настроен словарь / модель не вызвала tool / пустой индекс;
- Долгий ответ → много tool-раундов + тяжёлый запрос 1С;
- «Не видит код» → Qdrant пустой или Docker выключен.

# Часть J. Проблемы простым языком

| Что видите | Что это значит | Что делать |
|------------|----------------|------------|
| `docker` не найден | Docker не в PATH / не установлен | Установить Docker Desktop, новый PowerShell |
| Qdrant timeout | Контейнер не запущен | Docker Desktop + `start_qdrant_docker.ps1` |
| 401 от 1С | Неверный логин/пароль | `.env` + пользователь публикации |
| 404 от 1С | Неверный URL или нет сервиса | Публикация, `/hs/ai`, Module.bsl |
| Connection refused 1С | Веб-сервер 1С не слушает | Служба IIS/публикация, firewall |

| Агент «не находит код» | Нет points / Docker off / fallback | status, dashboard, Docker |
| Ответ выдуманный | Модель не сходила в tools | Правила, temperature↓, модель сильнее |
| Index часами | Нормально на 80k | Не прерывать; смотреть upserted |
| Excel / ссылка example.com | Модель выдумала URL | Брать путь только из ответа tool; локально `:8766` |
